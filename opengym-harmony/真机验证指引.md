# 鸿蒙版真机验证指引

## 一、装新包

新包在 `build\entry-default-unsigned.hap`（**218 MB**，2026-11-02 21:23 编译）。

> 应用名与包名沿用上游：`openGym` / `ch.duartesantos.opengym`。
> 若手机上装过改过名的那版，需先卸载再装（包名不同会并存两个应用）。

> 体积是动作媒体带来的：6554 张静帧（33 MB）+ 6554 段动画（157 MB）。
> 手机/平板的 HAP 上限是 4 GB，不构成问题。安装会慢一些，属正常。

**方式一：DevEco Studio（推荐）**

用 DevEco Studio 打开 `opengym-harmony/` 目录，等它同步完依赖，连上手机，点运行。
它会自己签名、装包、启动。

**方式二：命令行安装（手机需先开 USB 调试并授权）**

```bash
HDC="C:/Program Files/Huawei/DevEco Studio/sdk/default/openharmony/toolchains/hdc.exe"
"$HDC" list targets                      # 先确认设备已连上
"$HDC" install -r "opengym-harmony/build/entry-default-unsigned.hap"
"$HDC" shell aa start -a EntryAbility -b ch.duartesantos.opengym
```

> 未签名的包只能装在开了「开发者模式」的设备上。正式包需要在 DevEco 里配证书。

**手机侧设置**：设置 → 关于手机 → 连点「版本号」7 次进开发者模式 → 系统和更新 →
开发者选项 → 打开「USB 调试」。首次连接电脑时手机会弹授权框，要点允许。

## 二、看什么

### 正常的样子
打开后直接进主界面（训练列表 / 仪表盘），**底部有导航栏**，能左右滑动切换页面。

### 这次修的是什么
上一个包打开是 openGym 自己的报错页：

```
Could not load resource://rawfile/assets/index-Kr6mHU6B.js
```

原因是 ArkWeb 不让 `resource://` 协议加载 ES 模块。这次改成用 `https://localhost`
加载页面、由应用自己从包里喂资源。

**如果还是打不开**，抓日志看卡在哪：

```bash
HDC="C:/Program Files/Huawei/DevEco Studio/sdk/default/openharmony/toolchains/hdc.exe"
"$HDC" shell hilog | grep -E "Index|LocalAssets|Web"
```

日志里这几行是判断依据：

| 日志 | 含义 |
|------|------|
| `[Index] page loaded` | 页面加载完了（模块图起来了） |
| `[LocalAssets] not found: xxx` | 某个资源在包里找不到，会打印路径 |
| `[Index] page error: ...` | WebView 层面解析失败 |
| `[Index] intercept failed: ...` | 拦截回调自己出错了 |

## 三、逐项确认功能

按这个顺序走，每一步都确认了再往下：

**1. 启动**
- [ ] 应用能打开，不再显示报错页
- [ ] 进到主界面，看到训练数据（或空状态引导）

**2. 动作图与动画**（这次的重点）
- [ ] 动作位置显示**哑铃动作图**，不是那个中性的哑铃占位图标
- [ ] 点开一个动作，动画会**动**（不是静帧）
- [ ] 动画循环播放不卡顿（Android 版在这里出过「慢且卡」的问题）
- [ ] 切换动作、退出再进，动画仍能正常播

**3. 本地存储**
- [ ] 新增一条训练记录
- [ ] 完全退出应用再打开，记录还在（这验证 SecureStorage + 文件镜像）

**4. 底部导航**
- [ ] 各个标签页能正常切换
- [ ] 页面不卡死、不白屏

**5. 离线**
- [ ] 断网后仍能打开并查看已有数据
- [ ] 这验证 `https://localhost` 的资源拦截确实没依赖网络
- [ ] 断网后动作图仍能显示（媒体在包里，不在网络上）

**6. 配对服务器**（如果你要用这个功能）
- [ ] 在设置里配对局域网上的 openGym 服务器
- [ ] 配对成功、能同步
- [ ] 这一步最关键：服务器只接受三个 WebView Origin（`https://localhost`、
      `capacitor://localhost`、`http://localhost`），本应用用的是第一个。
      如果配对失败，看服务器日志里的 origin 值对不对。

**7. 权限与原生能力**（按需测）
- [ ] 训练提醒能弹通知（LocalNotifications + slot）
- [ ] 定位权限弹窗正常（GymReminder 的位置提醒）
- [ ] 分享可用
- [ ] 扫码可用（需要 HMS ScanKit，设备要带华为账号）

## 四、已知的问题与限制

| 项 | 说明 |
|---|------|
| HAP 未签名 | 只能装在开发者模式的设备上。要上架得在 DevEco 里配证书 |
| 图标是模板默认图 | 应用桌面图标还是 DevEco 的默认样式，要自己换 |
| AI 教练 | 原生 HTTP 通路已实现，但 TLS 与超时行为未在真机验证过 |
| nudge check | 问服务器「今天是否已在别的设备练过」只做了配置和存储，实际请求还没接 |
| `print` / `restAlert` | 鸿蒙侧明确不支持 |
| 桌面小工具 | 鸿蒙没有对应能力，明确 reject |

## 五、还有哪些没验证

三道自动化校验（静态 36 项、桥接 22 项、资源映射 236 项）覆盖的是**代码层面**的事：
配置对不对、接口契约对不对、路径映射和 MIME 类型对不对。

**ArkWeb 自己的运行时行为只有真机能验证**——比如 `onInterceptRequest` 拦主文档的时机、
模块请求的实际 CORS 判定、Worker 与 Service Worker 的加载。这些校验器管不到。

所以：**这次修复的成败，最终看手机上的表现。**
